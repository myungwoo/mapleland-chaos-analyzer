# 🌀 메이플랜드 혼돈의 주문서 분석기

혼돈의 주문서 60% 로 **원하는 능력치 조합을 만드는 최소 기대비용 전략**과 **손절 시점**을
계산한다. 시뮬레이션이 아니라 동적계획 엄밀해다. 계산은 전부 브라우저에서 끝난다.

```bash
npm run dev        # 웹 UI
npm test           # 엔진 검증 (닫힌 형태 · 독립 구현 · 몬테카를로 · 불변식)
npm run typecheck  # next typegen + tsc
npm run lint
npm run build      # 정적 내보내기 (out/)
npm run report     # 예제 시나리오 분석을 터미널에 출력
```

## 문제

혼돈의 주문서는 업횟을 1 쓰고, 60% 로 성공하면 **붙어 있는 능력치마다 따로** −5 ~ +5 를
굴린다(최대 HP·MP 는 10 단위). 실패하면 업횟만 준다. 0 이하로 떨어진 능력치는 사라져
다시 붙지 않는다.

입력은 아이템의 업횟·능력치와 목표, 아이템·주문서 가격, 실패작 회수가다. 목표는 두 종류다.

- **개별 최소값**: 힘 ≥ 6 처럼 능력치 하나에 거는 것
- **합 목표**(합스탯 작): 덱스 + 럭 ≥ 30 처럼 여러 능력치의 합에 거는 것. 사라진 능력치는 0 으로 친다.

모든 목표가 **동시에** 채워지는 순간 달성이고 거기서 멈춘다.
가망이 줄어든 아이템은 처분하고 새로 사서 다시 시작할 수 있다.

변화량 확률은 [유저 측정치](https://velog.io/@darkpppet/%EB%A9%94%EC%9D%B4%ED%94%8C-%ED%98%BC%EB%8F%88%EC%9D%98-%EC%A3%BC%EB%AC%B8%EC%84%9C-%ED%99%95%EB%A5%A0)를
자리표시자로 두었고 화면에서 바꿔 볼 수 있다.

## 엔진 구조 (`src/lib/chaos`)

| 파일              | 역할                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| `item.ts`         | 아이템 1개의 최적 정지 DP, 정책을 따라 굴린 사이클 결과 분포          |
| `solve.ts`        | 재시작이 있는 전체 문제 — 딩켈바흐 반복                               |
| `distribution.ts` | 총지출 분포(배가법), 아이템 개수 분위수, 능력치별 최종 분포           |
| `index.ts`        | `analyze` (화면용 묶음), `judge` (임의 상태 판정·매물 평가)            |

### 상태를 줄이는 법

상태는 (남은 업횟, 목표에 쓰이는 능력치마다의 수치)다. 목표에 안 쓰이는 능력치는 굴림이
독립이라 결정에 영향이 없으므로 뺀다.

- 능력치가 자기가 낀 목표의 min 보다 5u 넘게 높으면 혼자서 그 목표들을 영영 채우므로
  그 위는 한 칸으로 접는다 (다른 능력치는 0 이상이니까).
- 개별 최소값이 걸린 능력치는 −5u 아래가 가망 없음이고, 사라지는 것도 곧 실패다.
  합 목표에만 쓰이는 능력치는 다른 능력치가 메울 수 있어 자르지 않고 "소멸" 칸을 살려 둔다.
- 출발점에서 도달할 수 없는 범위는 애초에 두지 않는다.

축마다 0번 칸을 "실패", 1번을 "소멸"로 두면 성공 시 기대값이 축별 1차원 합성곱으로
쪼개진다(실패는 상수, 소멸은 굴림을 받아도 소멸).

업횟을 다 바른 **합**의 분포는 능력치별 분포를 더해서는 안 나온다(성공 여부를 공유한다).
성공 횟수 n 으로 조건을 걸면 능력치들이 독립이 되므로, 이항분포로 섞은 합성곱으로 정확히 구한다.

### 재시작 = 분수 최소화

정책을 고정하면 아이템 1개(사이클)마다 성공 확률 q, 바르는 장수 n 이 정해지고

    총비용 = (P + c·n − S·(1−q)) / q

이다. "포기하면 λ 를 다시 내고 S 를 받는다"로 놓고 아이템 하나를 풀어 정책을 얻고, 그
정책의 비율을 새 λ 로 삼는다(딩켈바흐). λ 는 단조 감소하고 보통 서너 번에 멈춘다.
출발점은 "가망이 있는 한 끝까지 바르기" 정책 — 손절은 성공 확률을 올리지 않으므로
이 정책의 q 가 최대이고, 0 이면 불가능하다.

### 총지출 분포

정책이 정해지면 사이클 결과는 (바른 장수, 성공 여부) 뿐이다. 실패 횟수가 기하분포라
수만 번까지 갈 수 있어서, 금액 격자 위에서 등비급수 Σ F^{*m} 를 배가법으로 합친다.
격자에 올릴 때 양 옆 칸에 나눠 실어 평균을 정확히 보존한다.

## 검증

- 닫힌 형태: 결정론적 경우, 단발 승부 `(P + c − S(1−q))/q`, 능력치 소멸(개별·합), HP 10 단위
- 독립 구현: 수치 튜플을 키로 쓰는 메모 재귀 + `R ← f(R)` 반복과 8자리 일치 (합 목표, 개별+합 혼합 포함)
- 합 분포: 업횟을 전부 펼쳐 센 값과 12자리 일치
- 정책을 그대로 4만 회 굴려 기대비용이 4σ 안, 분위수가 4% 안
- 단조성: 목표↑ 비용↑, 업횟↑ 비용↓, 주문서가↑ 비용↑, 회수가↑ 비용↓
